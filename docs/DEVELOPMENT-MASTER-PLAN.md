## 1. 项目定位

面向中国医生的「AI 数字人 + Agent 任务执行」一站式智能工作台：

- **核心差异**：不是问答工具，而是能执行任务、交付可验收成果的"数字人同事"
- **首发主打**：40 个医学科研技能（文献检索/解读/绘图/排版/写作，对标解螺旋 40 Skill，功能对标、内容自研）
- **旗舰功能**：医疗文献大模型驱动的 AI 数字人（对话 + 定制）
- **业务闭环**：医生提交任务 → 后台 AI 执行 → 合规审核 → 定向回传提交医生

## 3. 技术选型（一人维护原则：服务越少越好）

> 原团队版 Java 微服务方案废弃。一人公司只允许 **2 个服务 + 1 个数据库**。

| 层 | 选型 | 理由 |
|---|---|---|
| 应用主体 | **Next.js 15 全栈（TypeScript）**：Web 端 + API 路由 + 运营后台一体的单体 | AI 生成质量最高；一个仓库一个服务；Vercel/容器部署都简单 |
| AI 服务 | **Python FastAPI**（独立小服务）：RAG、文献检索工具、绘图引擎、Agent 编排 | LangGraph/Matplotlib 生态必须 Python；只做 AI，不做业务 |
| 数据库 | PostgreSQL（Supabase 托管起步）+ Prisma ORM | 认证/存储免费额度够 MVP；向量检索用 pgvector 免去 Milvus |
| 大模型 | 国产 API 矩阵（DeepSeek/Qwen/GLM 多路由）+ 医学 RAG（pgvector + ES 后置） | 一期不自训模型，API 成本最低；RAG 锚定 PubMed/指南原文抑制幻觉 |
| 数字人 | 第三方 API（一期），形象/声音克隆任务单制 | 不自研渲染 |
| 消息队列 | 起步用 PostgreSQL + BullMQ（Redis），不上 RocketMQ | 万级任务前足够 |
| 部署 | Vercel（Web）+ 单台云主机 Docker（AI 服务） | 月成本可控在 ¥500 内（不含模型 API 用量） |
| 桌面客户端 | **V1.5 再做**（Electron 壳包装 Web） | MVP 先 Web 验证需求 |
| 小程序 | **V2.0 再做**（uni-app） | — |
| 安全合规 | AES-256 + 内容安全 API + 生成式 AI/深度合成双备案（上线前完成） | 医疗 AIGC 前置条件 |

## 4. 系统架构（精简为 2 服务）

```
┌─ 医生 Web 端（Next.js）──────────────────────────┐
│ 数字人对话 ｜ 任务中心 ｜ 科研套件(40技能)          │
│ 内容工厂 ｜ 交付物中心 ｜ 会员/积分 ｜ 运营后台(/admin)│
└──────────────┬───────────────────────────────────┘
               │ REST/SSE
┌──────────────┴─ AI 服务（FastAPI）────────────────┐
│ 模型路由网关(多模型/计费/降级) ｜ Agent 编排(LangGraph)│
│ 医学工具集(PubMed/万方检索, PDF解析) ｜ 绘图引擎     │
│ 数字人 API 适配层 ｜ 内容合规预审 ｜ 技能包(.mskill)解析│
└──────────────┬───────────────────────────────────┘
               │
┌──────────────┴─ 数据层 ───────────────────────────┐
│ Supabase: PostgreSQL(+pgvector) ｜ Auth ｜ Storage │
│ Redis(BullMQ 异步任务) ｜ 对象存储(产物/渲染成片)    │
└───────────────────────────────────────────────────┘
```

**核心业务流**：医生在 Web 提交任务单 → 入 BullMQ 队列 → AI 服务按技能路由执行（长任务异步，关浏览器不中断）→ 合规预审 → 状态回写 + 站内/微信通知 → 交付物中心预览/追问/下载。

### 5.2 40 科研技能落地批次（功能对标解螺旋，自研实现）

| 批次 | 版本 | 技能 |
|---|---|---|
| B1 | MVP | 文献检索（PubMed+万方三库路由）、文献解读（PDF/PMID→结构化拆解，缺失标 Not specified）、数据分析可视化（首批 12 图：火山/热图/生存曲线/ROC/森林/箱线/小提琴/韦恩/气泡/柱状/散点/富集条形）、参考文献管理（PMID 补全 + 9000+ 格式 + GB/T 7714） |
| B2 | V1.5 | 实验设计、临床方案设计（国自然格式）、综述写作（建库→分章→校验，真实 PMID）、论著写作（三分型框架）、文风改写、补充 12 图（GSEA/曼哈顿/漏斗/校准/DCA/列线图/QQ/密度/云雨/雷达/饼图/弦图） |
| B3 | V2.0 | 标书/统计咨询（国自然完整套件）、补充 6 图（Circos/PPI/桑基/时序/敏感性/相关性热图） |

**合规红线（承袭原文架构）**：事实类技能（检索/解读）强制走数据库工具不脑补，引用必须真实 PMID 可溯源；分析类技能只搭架子，生成物强制带"AI 辅助仅供参考"声明。

### 5.3 WorkBuddy 能力迁移（P0 子集）

自然语言任务下达、Plan 先确认再执行、任务拆解编排、多模态交付、任务列表/继续处理、异步云端执行、多模型切换、免费积分体系 —— 随 P0 模块实现；本地沙盒文件、专家 Agent 矩阵、IM 集成、技能市场、MCP、定时自动化 → V1.5/V2.0。

## 8. AI 开发工作流规范（总纲核心章节）

**每张任务卡的循环**：
1. 创始人从 Sprint 任务卡选 1 张 → 交给 AI（Trae）
2. AI 实现（含单测）→ 自报完成
3. **三关验收**才可合入：① `lint + 测试全绿 + 安全扫描零高危`；② AI 生成代码抽检（人读关键路径）；③ 人工冒烟（真机点一遍主流程）
4. 合入主分支，任务卡关闭

**工程约定**：
- 单仓（monorepo）：`apps/web`（Next.js）+ `apps/ai`（FastAPI）+ `packages/shared`
- 分支：每任务卡一分支， squash merge；提交信息 `feat|fix|docs: 描述`
- 数据库：Prisma migration 管理，禁止手改线上表
- 环境变量/密钥一律 `.env`，不入库；模型 API Key 只存服务端
- 每周五打 tag（`v0.x`），线上部署与 tag 绑定
- 代码覆盖率目标 ≥60%（MVP 期），AI 服务核心工具函数 ≥80%

## 9. 风险与对策（一人公司特化）

| 风险 | 对策 |
|---|---|
| **单人带宽不足（最大风险）** | Sprint 范围刚性锁定；一切 P1/P2 来了先记账不开发；用 AI 并行但人只做一个验收者 |
| 大模型幻觉误导临床 | RAG 强制溯源；用药剂量等高风险只检索不建议；生成物全量免责声明 |
| 数字人第三方依赖 | 双供应商接入 + SLA 条款 |
| 医疗合规 | 双备案与开发并行；律师按次咨询前置审核商业化文案 |
| 技能仿写知识产权 | 功能对标、提示词/工作流自研，不复制解螺旋文件内容 |
| C 端付费不足 | B 端药企为盈利锚点，C 端会员仅覆盖 API 成本 |
